# QA PLAN

## 各機能の終了条件

仕様→小さい実装→Godot起動→再現可能な試験→修正→再試験→文書更新。
エラーをログから除外しない。クラッシュ、セーブ消失、進行不能、物語条件の不達をP0。
操作不能、避けられない通常攻撃、読みづらい重要UI、恒常的な大幅FPS低下をP1。
P0/P1が残る状態で次の量産フェーズへ行かない。

## 自動化する試験

- 固定版Godotでimportとparse、main sceneを起動して終了。
- 必須入力定義、物理120Hz、補間、nearest、整数スケール、2D制約。
- 設定の往復、無効な型/値、破損ファイル、バックアップ復旧、未来schema拒否。
- 全基本シーンをinstantiateし、title→設定→チェック画面→creditsを遷移。
- 将来: 移動距離のFPS比較、射撃間隔、弾薬保存、投擲、敵知覚、ダメージの一度だけ適用。
- 将来: 分岐表、ストーリー矛盾、セーブ中断、全結末をfixtureで通す。

## 人/実画面で確認する試験

720p/1080p/1440p/4Kで日本語が読める、フォント欠字ゼロ、黒帯、UIクリッピング、
ウィンドウ/フルスクリーン、Alt+Tab、Esc、マウス/キーボード、DPI100/150/200%、
フォーカス喪失中の誤射、複数モニター、小さいモニターへ設定ファイルを移した時の復旧。
60/120/144/165/240/360Hzモニターの体感は実際の対応機材でのみ合格にできる。
自動スクリーンショットはレイアウト確認の証拠。人の操作感評価の代替ではない。

## M01観察

初見3名以上、操作説明を口頭で補足せず、部屋ごとの所要時間/死因/迷い/弾切れを記録。
中央値5–10分。話の理解、撃つ→滑る→奪うの連係、パズルの手がかりを説明できるか聞く。
死亡20回連続、ポーズ100回、扉の出入り、投擲武器の山、Blood0/最大でソフトロックなし。
同じ死亡演出が偏る場合はHitContextと選択履歴をログから点検する。

## 負荷計測

基準機はPhase 9までに実機スペックと合わせて確定する。未計測のFPS保証を記載しない。
室内通常戦と最悪負荷（AI24、血512粒、動的死体12）でCPU/GPU時間とp95/p99を記録。
tickを落として速度差を隠さない。視覚密度を削る時はゲーム上の情報を保持する。
